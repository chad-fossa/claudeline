On 2026-07-06 the user's `claude-personal` profile statusline displayed the **work** profile's usage numbers, while Claude Code's own `/status` command correctly showed per-profile numbers. This is the textbook symptom of [[leak-inventory]] item 1 (keychain single-slot): `/status` gets its data through a different, properly-isolated path, while `hooks/show-usage-limits.sh`'s `get_token()` hits the one shared macOS keychain entry and picks up whichever account last ran `/login`.

Deployment context: both profiles were wired via dotfiles symlinks, with both profiles' `settings.json` pointing at `~/.claude`-rooted paths for the statusline command and hooks (matching [[leak-inventory]] item 5 — install.sh/settings-example.json have no per-profile path awareness by construction). This is consistent with — not necessarily proof of — the hardcoded-path item 3, though item 3's internal `ACCOUNT_ID` re-derivation should have compensated for that specific piece; the actual observed divergence traces to the keychain, not the hook path.

**Why this matters:** confirms item 1 is not just a theoretical upstream limitation (#20553) but an actively-experienced bug for this user, on this exact dotfiles setup, on this date. Any future report of "personal shows work's numbers" (or vice versa) should be diagnosed against this same root cause first before assuming a new bug.
